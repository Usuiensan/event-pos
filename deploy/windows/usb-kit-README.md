# Windows USBキット

`Start-USB-Kit.bat`をダブルクリックすると、コマンドプロンプト1つでPOS serverとPrinterHostを起動し、ブラウザーを開きます。Docker DesktopやNode.jsの事前インストールは不要です。

初回はイベント情報を入力します。商品一覧は空で、管理者の責任者番号は `001` です。終了時は Ctrl+C を押し、DBの書き戻しが完了してからUSBを取り外してください。

## アップデート（新しいプログラムへの更新）

キット内の`Update-USB-Kit.bat`をダブルクリックすると更新できます。どのPCでも動きます（Windowsとネット接続だけ必要です）。

- ふだんは GitHub の配布リリースから新しいプログラムを取得して反映します。既に最新なら「既に最新です」と表示して終わります
- DBと初期設定（`event-config\usb-kit-initial`）は保護され、変化していたら更新前の状態へ自動で戻します
- 更新中はキットを起動しないでください。旧版のアップデーターで許可されていないファイルのエラーが出る場合は、POSを正常終了してから、開発PCで同じキットフォルダーに新版をビルドしてください
- 更新前のプログラム一式はそのPCの`%LOCALAPPDATA%\EventPos\UsbKit\update-backup`に残ります
- アップデーター自体の新版は、次回`Update-USB-Kit.bat`を起動したときに自動で差し替わります（旧版は`update-usb-kit.ps1.prev`に残ります）

ビルド元PCでは、リポジトリから直接ビルドして反映することもできます。その場合は環境変数`EVENT_POS_UPDATE_MODE`に`local`を設定してから実行してください（ビルド元は`EVENT_POS_REPO`で変更できます）。

配布リリースの作成は、ビルド元PCで`deploy\windows\publish-kit-release.ps1`を実行します（GitHubトークンが要ります）。

## ウィンドウの「×」とWindowsのシャットダウン

コマンドプロンプトを「×」で閉じたり、Windowsでシャットダウンやサインアウトを行ったりすると、終了通知を受け取った時点で会計の受付を止めてUSBへ最終保存を試みます。通常のシャットダウンと再起動では、Windowsに「ぽすりんの会計データをUSBへ保存しています」と伝え、最長10秒を目安に終了処理を待ちます。保存が終わった時点で待機を解除します。Windowsが先にプロセスを終了した場合は、次回起動時の自動復旧で書き戻します。

## DBの復旧（強制終了・電源断で起動できなくなったとき）

会計はPC側のSQLite DBへ確定時に保存します。稼働中は5秒ごとに変更を調べ、変更があれば確定済みDBをUSBへ保存します。USBが抜けてもPC側に保存済みの会計は残ります。コマンドプロンプトにUSBへの保存エラーが表示され、同じUSBが元のドライブ文字に戻ると再試行します。ブラウザーの画面や設定など、USB上のファイルを使う操作にはUSBの再接続が必要です。USBだけで復旧する場合は最後に完了した保存時点までです。

強制終了や電源断の後は、**同じPC、同じWindowsユーザー、同じUSB**で `Start-USB-Kit.bat` を起動してください。PCに残ったSQLite DBを検査し、確定済みのデータをUSBへ書き戻してからPOSを起動します。書き戻しが終わるまで別のPCではこのUSBを使えません。

旧版で強制終了した場合は、復旧情報からUSBを識別できないため手動復旧が必要です。前回使ったUSBを挿して、そのUSB内の `Recover-USB-Kit-DB.bat` を実行してください。ローカルDBは `%LOCALAPPDATA%\EventPos\UsbKit\data` にあります。

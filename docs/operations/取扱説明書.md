# event-pos 取扱説明書

## 1. 開場前

1. POSサーバー、PrinterHost、TM-T70II、顧客画面、各レジ端末を起動する。
2. 責任者の「運用ダッシュボード」でDB readiness、PrinterHost、印刷件数、空き容量、最終バックアップ、各端末の最終通信を確認する。`unknown`は正常とみなさない。
3. TM-T70IIの電源、USB、用紙、カバーを目視する。テスト印字を1枚出し、日本語、金額、フィード、部分カットを確認する。
4. DBと成果物保存先が当日のevent用であることを確認する。本番では`POS_ARTIFACT_ROOT`を明示し、同期フォルダーや一時フォルダーを直接の正本にしない。

## 2. 開局と準備金

業務メニューの「開局・点検・精算」を開き、event、営業日、現金箱を確認して営業開始する。金種ごとの準備金を数え、数量を入力して開局を確定する。合計だけを逆算入力せず、実際に数えた金種を記録する。

誤った営業日や現金箱で開始した場合は販売を始めず、責任者へ連絡する。確定済み記録をDBから直接削除しない。

## 3. 販売

商品を登録し、顧客画面の品名・数量・金額を確認する。R18商品は所定の確認を完了してから会計する。現金では預り金と釣銭を読み合わせ、外部決済では端末側の成功を確認してからPOSを確定する。

会計が確定し、印刷だけ失敗した場合、売上をもう一度確定しない。印刷状態を確認し、紙面の現物結果を「印刷済み・未印刷・不明」から選んで再印刷する。不明時は二重印刷の可能性を顧客と責任者へ説明する。

## 4. 入金・出金

両替補充など売上以外の現金増減は「入金・出金」から登録する。金額、理由、担当者を確認して確定する。現金台帳と合わなくなるため、箱の現金だけを動かさない。

## 5. 中間点検

販売を一時止め、箱内の金種を数えて入力する。画面の理論現金、実在高、過不足を確認し、中間点検を確定する。確定後は点検紙面と、DB backup・Excel・manifestの成果物生成が別々に進む。

成果物が失敗しても点検記録は確定済みである。点検をやり直さず、運用ダッシュボードで失敗理由と保存先を確認し、責任者が同じ確定記録から再生成する。

## 6. 全部返品

業務メニューの「返品」から元取引を受付番号などで検索する。商品、金額、支払を照合し、返品理由を入力して責任者権限で確定する。元売上は変更されず、返品取引、在庫戻し、返金、監査、返品レシートが追記される。

初期版は元取引の全部返品のみである。一部だけ返品する場合は全部返品後、残す商品を新規売上として登録する。クレジット・売掛など外部返金は確認フローが未受入のため、この画面では返品できない。現金と無料取引だけを対象とする。

## 7. 精算と翌日残し

販売終了後、未処理会計と印刷状態を確認する。金種別実在高と翌日残しを入力し、理論現金、過不足、回収額を読み合わせて精算する。確定後の成果物が成功し、DB backup、単一xlsx、manifestが同じ成果物IDとhashでそろったことを確認する。

精算後に営業を再開する場合は理由を記載し、責任者が承認する。再開は元の精算を削除せず、監査記録を残す。

## 8. 終了と障害時

- 最終バックアップの成功時刻、保存先、hash、空き容量を確認する。
- `pending`は処理中、`failed`は失敗、`unknown`は結果不明であり、いずれも成功扱いにしない。
- USB切断や送信途中停止では自動再送しない。接続復旧後、現物結果を確認して明示再印刷する。
- DB、backup、manifest、Excelの役割は別である。Excelだけを正本にしない。
- DBファイル、WAL、成果物を営業中に手作業で移動・上書きしない。

終了時は当日の精算、成果物、未解決の印刷job、過不足、返品を責任者が引き継ぎ記録へ残してから端末を終了する。

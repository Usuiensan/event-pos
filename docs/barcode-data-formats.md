# バーコードリーダー入力の規格・データ形式一覧

## 目的と前提

この文書は、バーコードリーダーがPOSへキーボード入力またはシリアル入力として渡す数字列・文字列を、**規格上の意味を推定するための資料**としてまとめたものです。

重要な前提は次のとおりです。

- 読み取った文字列だけでは、元のバーコードシンボル（EAN-13、Code 128、QRなど）を常に判別できない。可能ならリーダーのAIM Symbology Identifier（例: `]E0`、`]C1`、`]Q3`）も受け取る。
- バーコードの見た目・規格上のチェック文字と、リーダーが出力するデータは別物である。Code 128のシンボルチェック文字は通常、出力文字列には含まれない。
- 先頭ゼロ、固定長、英字の大文字小文字、GS1の制御文字（FNC1、入力後はASCII Group Separator `0x1D` として渡る場合がある）を壊さず、文字列として保存する。
- 人間可読文字列の括弧は、GS1 Application Identifier（AI）を示す表示用の記号であり、通常はバーコードデータに含まれない。
- 「数字だけ」「8桁」「13桁」だけで商品コードと断定しない。チェックデジット、登録済み商品、AIM識別子、GS1構文、画面コンテキストを順に確認する。

## 1. まず分けるべきもの

| 分類 | 例 | POSでの扱い |
|---|---|---|
| GS1識別キー | GTIN、GLN、SSCC | 桁構造とモジュラス10を検証する |
| GS1要素文字列 | `(01)04912345678907(17)261231(10)ABC` | AIごとに切り出す。可変長AIの終端にFNC1/GSが必要 |
| 非GS1一次元コード | Code 39、Code 128、NW-7、ITF | シンボル規格の文字集合・内部チェックを検証する |
| 二次元コード | QR Code、Data Matrix、PDF417、Aztec | payloadを文字列またはバイト列として扱う。桁の意味は規格またはアプリ仕様次第 |
| POS内部コード | `PS111234`、取り置き番号など | GS1と混同しない独自名前空間として完全一致で解決する |
| キーボード入力 | `123`、`1000` | バーコードでない可能性があるため、金額入力と商品検索を別バッファで扱う |

## 2. 数字だけの主な規格

### 2.1 EAN-13 / JAN-13（GTIN-13）

日本の商品で最も一般的な13桁の小売商品コードです。JANはEAN-13の日本での呼称です。

| 位置 | 意味 |
|---|---|
| 1〜12桁目 | GS1事業者コードと商品アイテムコード。境界は固定ではなく、GS1事業者コードの桁数により変わる |
| 13桁目 | モジュラス10のチェックデジット |

先頭1桁は「国コード」と単純に解釈してはいけません。GS1 Prefix（日本の通常の商品では`45`または`49`がよく現れる）は、GS1加盟組織・番号範囲を示すもので、製造国そのものを保証しません。

### 2.2 EAN-8 / JAN-8（GTIN-8）

| 位置 | 意味 |
|---|---|
| 1〜7桁目 | GS1-8事業者プレフィックスと商品番号 |
| 8桁目 | モジュラス10のチェックデジット |

小型商品向けです。EAN-13へゼロ埋めして意味を変えるのではなく、元のGTIN-8を保持します。

### 2.3 UPC-A（GTIN-12）

| 位置 | 意味 |
|---|---|
| 1桁目 | Number System |
| 2〜6桁目 | GS1 Company Prefixの一部 |
| 7〜11桁目 | 商品番号 |
| 12桁目 | モジュラス10のチェックデジット |

UPC-EはUPC-Aの短縮表現で、読み取り機がUPC-Aへ展開して出力する設定もあります。POSでは、リーダー設定とAIM情報を確認せずに桁数だけでUPC-Eかどうかを決めないでください。

### 2.4 EAN-14 / GTIN-14

GTIN-14は14桁の論理的な識別子です。EAN-13に先頭ゼロを付けたGTIN-14や、ケース・集合包装用のインジケータ付きGTIN-14があります。

| 位置 | 意味 |
|---|---|
| 1桁目 | インジケータ。集合包装の識別など。GTIN-13をGTIN-14へゼロ拡張する場合は`0` |
| 2〜13桁目 | 元のGS1事業者コード・商品アイテムコード等 |
| 14桁目 | モジュラス10のチェックデジット |

GTIN-14は識別子の形式であり、必ずしも印刷シンボルが「EAN-14」という意味ではありません。

### 2.5 ITF-14

ITF-14は、通常、14桁のGTIN-14だけを運ぶ物流・集合包装向けのInterleaved 2 of 5シンボルです。

- データ: 数字14桁。
- 桁の意味: GTIN-14と同じ。
- 最終桁: GTINのモジュラス10チェックデジット。
- 数字を2桁ずつ組にしてバーとスペースへ交互に符号化する。奇数桁の自由な文字列を入れる規格ではない。
- GTINを運ぶ目的であり、ロット番号・期限・シリアル番号は通常別のGS1-128等を使用する。

### 2.6 ISBN-13 / ISSN / ISMN

書籍・逐次刊行物の識別子です。商品価格や出版社名を自由に含むものではありません。

| 規格 | 通常の表示 | 検査 |
|---|---:|---|
| ISBN-13 | 13桁 | GTIN-13と同じ重みのモジュラス10 |
| ISBN-10 | 10文字（最後は`0`〜`9`または`X`） | 重み10〜1の合計が11の倍数。`X`は10 |
| ISSN | 8文字（表示は`xxxx-xxxx`） | 先頭7桁に重み8〜2。最後の`X`は10。合計が11の倍数 |
| ISMN | 現行は13桁で先頭`979-0` | ISBN-13と同じモジュラス10。旧10桁形式は別処理 |

ISBN-13は通常EAN-13/JAN-13として印刷されます。ISBN-10やISSNをJANと同じ13桁として扱わず、用途を保持します。

### 2.7 日本の定期刊行物JAN

雑誌等では、本体の商品識別用バーコードと、価格・号・年月を表す2段目バーコードが組み合わされることがあります。コード体系や価格の桁解釈は、一般の商品JANと異なります。

- 13桁の商品識別部だけで価格・号を推測しない。
- 2段目の価格情報を利用する場合は、定期刊行物JANの規格に従い、対象商品種別を確定してから解釈する。
- POSでは商品マスタの価格を勝手に上書きせず、許可された商品種別・税区分・価格範囲を検証する。

### 2.8 インストアマーキング（02、20〜29等）

店舗・事業者内で発行する可変商品・量り売り等のコードです。先頭範囲だけで全国共通の商品名や価格を決められません。

- 先頭範囲、残りのデータ構造、価格・重量の桁位置は発行者ごとの運用定義が必要。
- 例として`20`〜`29`を使う運用があるが、全ての20〜29コードが同じ価格形式とは限らない。
- 未登録コードは推測登録せず、対象イベントのマスタまたは管理者の明示登録へ回す。

## 3. GS1 Application Identifier（AI）形式

GS1-128、GS1 DataMatrix、GS1 QR Code、GS1 DataBar Expanded等では、複数の項目をAIで連結します。

### 3.1 基本構文

人間可読表示:

```text
(01)04912345678907(17)261231(10)ABC123(21)SN-9
```

実データの概念:

```text
01049123456789071726123110ABC123<GS>21SN-9
```

括弧は表示上の区切りで、通常は符号化データに含めません。AI `10`（ロット）や`21`（シリアル）のような可変長項目が後続する場合、次のAIとの境界をFNC1/GSで示します。

### 3.2 よく使うAI

| AI | データ | 形式 | 意味 |
|---|---|---|---|
| `00` | 18桁 | N18 | SSCC（物流単位） |
| `01` | 14桁 | N14 | GTIN |
| `02` | 14桁 | N14 | 梱包内商品のGTIN。通常AI `37`と組み合わせる |
| `10` | 最大20文字 | X..20 | ロット番号・バッチ番号。可変長 |
| `11` | 6桁 | N6 `YYMMDD` | 製造日 |
| `13` | 6桁 | N6 `YYMMDD` | 梱包日 |
| `15` | 6桁 | N6 `YYMMDD` | 賞味期限・品質保持期限 |
| `17` | 6桁 | N6 `YYMMDD` | 使用期限 |
| `21` | 最大20文字 | X..20 | シリアル番号。可変長 |
| `30` | 最大8桁 | N..8 | 数量（可変） |
| `37` | 最大8桁 | N..8 | 梱包内数量。可変長 |
| `310n` | 6桁 | N6 | 正味重量（kg）。`n`が小数桁数 |
| `320n` | 6桁 | N6 | 正味重量（lb）。`n`が小数桁数 |
| `392n` | 最大15桁 | N..15 | 通貨指定付き可変価格 |
| `393n` | 通貨3桁 + 最大15桁 | N3+N..15 | 通貨指定付き価格 |
| `414` | 13桁 | N13 | 物理的場所のGLN |
| `422` | 3桁 | N3 | 原産国ISO 3166 numeric |
| `7003` | 6桁 | N6 `YYMMDD` | 医療等で使われる有効期限系AIの一例 |

`n`を含むAIは、`3103`ならkgを小数3桁で表すなど、AIそのものの末尾が小数点位置を指定します。AIの全一覧・業界ごとの利用条件はGS1 General Specificationsを正本とします。

### 3.3 GS1の形式記号

- `N`: 数字。
- `X`: GS1で許可される英数字・記号。
- `N2`: 数字2桁固定。
- `N..8`: 数字、最大8桁の可変長。
- `X..20`: 英数字、最大20文字の可変長。
- 日付 `YYMMDD`: 年は2桁で、世紀は業務ルールと基準日から解釈する。`00`〜`49`を2000年代とする等の単純な固定解釈をアプリ独自に作らない。

## 4. 文字列を持てる一次元バーコード

### 4.1 Code 128 / GS1-128

Code 128は高密度の英数字・制御文字用シンボルです。Code Set A/B/Cを切り替えます。

| Code Set | 主な文字 |
|---|---|
| A | ASCII制御文字、英大文字、数字、記号 |
| B | ASCII英大小文字、数字、記号 |
| C | 数字2桁を1シンボルとして高密度に表現 |

GS1-128はCode 128の先頭にFNC1を置き、GS1 element stringを運ぶ用途です。通常のCode 128とGS1-128を同じ「英数字コード」として処理せず、AIM識別子やFNC1の有無を確認します。

Code 128のシンボルチェックは次で計算します。データの先頭をスタート値、後続シンボルを左から`v_i`、重みを1から順に置きます。

```text
check = (start_value + Σ(v_i × i)) mod 103
```

この`check`はバーコード内部の誤読検出用で、通常のスキャン出力payloadには含まれません。

### 4.2 Code 39

数字、英大文字、`- . space $ / + %`を基本文字集合とする古い一次元規格です。拡張Code 39では小文字等を2文字の組み合わせで表す場合があります。

- start/stop文字は通常`*`ですが、リーダー出力で除去されることがある。
- Mod 43チェック文字はオプション。出力に含めるかはリーダー設定による。
- `*`を含む入力、チェック文字の有無、拡張モードを設定依存にしない。

### 4.3 NW-7 / Codabar

数字、`- $ : / . +`および開始・終了文字`A`〜`D`を使える日本で帳票・図書館・医療用途に残る規格です。開始終了文字をリーダーが出力する設定としない設定があります。チェックデジットは標準必須ではありません。

### 4.4 Interleaved 2 of 5（ITF / I25）

数字だけを2桁単位で符号化します。ITF-14はGTIN-14専用の運用ですが、一般のITFは任意の偶数桁数字を運ぶ設定もあります。桁数だけでITF-14と断定しないでください。

## 5. 二次元コード

### 5.1 QR Code

QR Codeは「桁ごとの意味を持つ商品コード」ではなく、payloadを複数のモードで運ぶ二次元シンボルです。

| モード | データ |
|---|---|
| Numeric | 数字 |
| Alphanumeric | `0-9 A-Z space $ % * + - . / :` |
| Byte | バイト列。UTF-8等の文字コードはアプリ仕様 |
| Kanji | QR CodeのKanjiモード。文字集合・変換規則に注意 |

Version 1〜40、誤り訂正レベルL/M/Q/Hがあります。誤り訂正はReed–Solomon符号で、復元可能量は環境・配置に依存し、単純に「30%まで必ず読める」という意味ではありません。

QRのpayload例:

```text
https://example.test/product/04912345678907
POS:PS111234
{"productCode":"00001234","name":"sample"}
```

QR CodeにGS1 AIを入れる場合は、GS1 QR Codeの構文またはGS1 Digital Link URIなど、採用した仕様を明示します。通常のQR文字列をGS1-128のAI形式として推測しません。

### 5.2 Data Matrix / GS1 DataMatrix

通常のData Matrixは任意の文字列・バイト列を運べます。GS1 DataMatrixはFNC1を使い、GS1 element stringとしてAIを連結します。

- GS1 DataMatrixは画像式スキャナが必要。レーザー専用リーダーでは読めない場合がある。
- Data Matrixのpayloadは、AIM識別子とFNC1の扱いを含めて確認する。
- 通常のData MatrixとGS1 DataMatrixを、同じ数字列だからという理由で混同しない。

### 5.3 PDF417 / MicroPDF417

帳票、運転免許証、航空券などで使われる積層型コードです。複数行の英数字・バイト列を運べます。桁の意味は採用した帳票仕様に依存し、PDF417自体から商品コードや価格を推測できません。

### 5.4 Aztec、MaxiCode、その他

Aztecはチケット・モバイル搭乗券等、MaxiCodeは物流用途等で使われます。いずれも、シンボル規格はデータの意味を決めません。AIM識別子、業界仕様、アプリケーションIDをセットで扱います。

### 5.5 公共料金・税・保険料などの収納バーコード

日本のコンビニ収納用払込票で使われる標準料金代理収納バーコードは、現在は**GS1-128の1段表示・44桁固定長（実質42桁）**が標準です。これは商品JANではなく、収納処理のためのコードです。

標準料金代理収納ガイドライン第6版のコード体系は次の構成です。

| 項目 | 桁・形式 | 意味 |
|---|---:|---|
| AI | `91` | 収納用のアプリケーション識別子 |
| 請求書発行企業コード | 6桁 | GS1事業者コード7桁から先頭の`4`を除いたもの |
| 自由使用欄 | 21桁未満をゼロ補完 | 顧客番号等。発行企業の定義に従う |
| 再発行区分 | 1桁 | 初回`0`、再発行回数等 |
| 支払期限日 | 6桁 `YYMMDD` | コンビニ等で支払可能な期限日 |
| 印紙フラグ | 1桁 | `0`=不要、`1`=200円印紙、`2`〜`9`=予約 |
| 支払金額 | 6桁 | 請求金額。標準仕様の金額欄 |
| 全体チェックデジット | 1桁 | 直前までの43桁に対するモジュラス10 |

注意事項:

- `91`以降の収納用ペイロードを、`01`のGTINや商品価格と解釈しない。
- 支払金額は通貨・収納可否・期限・再発行状態と一体で扱い、商品販売の価格マスタへ登録しない。
- 地方税、国民健康保険、年金、電気、ガス、水道、電話、保険、授業料等で使われるが、請求元・収納代行会社固有の運用差があり得る。標準44桁に見えない場合は発行元の仕様を優先する。
- 旧来のJAN 3段/4段方式の払込票を見かけても、通常の商品JANとして商品検索しない。
- POSで公共料金を受け付けるには、バーコードを読めることだけでなく、収納業務、現金受領、領収証、取消・再発行、期限超過、印紙の業務要件が必要。商品販売POSのバーコード処理へ流用しない。

## 6. 出版物コード（雑誌・書籍・ISBN・ISDN）

### 6.1 ISBN

ISBNは書籍を識別する国際番号で、価格を直接表す番号ではありません。

- ISBN-13は通常`978`または`979`で始まる13桁。EAN-13/JAN-13として印刷される場合は、13桁全体にGTINモジュラス10を適用する。
- ISBN-10は9桁の本体とチェック文字1桁。最後の`X`は値10で、重み10〜1の合計が11の倍数になる。
- ISBN-10からISBN-13へ変換する場合、旧10桁のチェック文字を単に残さず、`978` + ISBN-10の先頭9桁を材料に新しいISBN-13チェックデジットを計算する。
- ISBNは商品名、著者、出版社、定価を自動的に含まない。検索サービスの候補は根拠確認後に個別採用する。

### 6.2 書籍JAN（二段バーコード）

書籍JANは、書籍の表面や裏面に**上段と下段の2本**で表示される出版物向けのJAN体系です。

#### 上段: ISBNのJAN化

上段はISBN-13をEAN-13/JAN-13として表します。構造は次のとおりです。

```text
978/979 + ISBNの出版者記号・書名記号 + ISBN-13チェックデジット
```

上段だけでは、書店流通上の定価を確定する用途には不十分です。

#### 下段: 価格・出版物情報のアドオン

下段は上段に付加される2桁または5桁等のアドオンで、**本体価格などを出版物JANの規則で表す**ものです。アドオンは独立したJAN商品コードではありません。

- 下段の先頭区分、価格欄、チェック文字、予備欄の意味は、書籍JANの版・出版物区分の規定に従う。
- 下段の価格は本体価格であり、税込価格へ変換するときは販売時点の税率・端数規則を適用する。
- `本体価格が10,000円以上`の扱いなど、価格欄に特殊な表現規則がある。下段を一般的な5桁商品コードとして商品マスタへ登録しない。
- 上段と下段を同一商品・同一読取単位として関連付ける。下段だけ読めた場合は、ISBN・上段が取れないため商品を一意確定しない。
- アドオンにはシンボルのチェック機能があるが、リーダーがチェック文字を出力するかは設定依存。読み取り文字列をそのまま価格と断定しない。

### 6.3 雑誌コード・定期刊行物JAN

雑誌は、書籍JANとは別に雑誌コード／定期刊行物コード体系を持ちます。雑誌コードは誌名・タイトル等を識別する5桁コードを基礎とし、発行形態により月号、週号、発行月、通巻などの情報を組み合わせます。

雑誌の付加コードでは、一般に次のような情報が現れます。

| 項目 | 意味 |
|---|---|
| 雑誌コード | 誌名・シリーズの識別 |
| 発行月・発行日号 | 月刊、週刊、日号等の発行情報 |
| 通巻 | 通巻号数。区分により使用 |
| 価格 | 本体価格。価格の桁・例外は出版物規定に従う |
| チェック | アドオンまたはシンボルの誤読検出用 |

雑誌の2段目・アドオンは、号数や本体価格を含むことがありますが、すべての雑誌で同じ桁配置とは限りません。雑誌コード、発行月/号、年、チェック、予備、価格を固定位置で推測せず、出版物コードの対象区分を確定してから解析します。

### 6.4 ISDN（同人誌等の国際標準同人誌番号）

ISDNは同人誌・自主制作出版物等で使われる識別番号です。本POSで扱う現行形式は、数字13桁のISDN本体を文字列として保持します。例:

```text
2784702901978
```

一般的な解釈:

| 部分 | 意味 |
|---|---|
| `278`系 | ISDNの識別領域。`279`等の拡張を含むかは採用規格・サービス仕様を確認 |
| 中間部分 | 出版者・作品等の番号。固定の一般商品JANの事業者コードと同一視しない |
| 最終桁 | ISDN/ISBN系の検査規則に基づくチェックデジット |

ISDN検索サービスから返る作品名、発行者、価格等は外部情報であり、コードそのものに全て埋め込まれているわけではありません。ISBNと同じ`978/979`の書籍JANとして扱わず、ISDNとして検索・マスタ関連付けします。

ISDNに付随する`292`で始まる2段目コードが提供される場合は、価格等の付加情報として返されることがあります。`292`だけを見て一般のインストアコードやGTINとして登録せず、ISDN本体と同じ出版物レコードに関連付け、取得元の仕様・価格単位・チェック結果を保存します。

### 6.5 読み取り順序

書籍・雑誌を1冊読むときは、次の順に処理します。

1. 上段のISBN/ISDN/雑誌識別コードを読む。
2. 下段・アドオンを読む場合は、上段の直後の付加データとして候補化する。
3. ISBN、雑誌コード、ISDNの種別を確定し、チェックデジットを検証する。
4. 書誌検索または商品マスタで作品を特定する。
5. 下段の本体価格を採用する場合は、付加コードの規格と通貨・税区分を確認する。
6. 上段なし・下段だけ、または種別不明の場合は自動登録せず、管理者確認へ送る。

## 7. チェックデジット計算

### 6.1 GTIN / EAN / UPC / JAN: モジュラス10（GS1方式）

チェックデジットを除いた数字列を右端から見て、重み`3,1,3,1,...`を掛けます。合計を`S`とすると:

```text
check = (10 - (S mod 10)) mod 10
```

例: `400638133393`（12桁）

```text
右から: 3 9 3 3 3 1 3 8 3 6 0 0
重み:   3 1 3 1 3 1 3 1 3 1 3 1
合計 S = 89
check = (10 - (89 mod 10)) mod 10 = 1
GTIN-13 = 4006381333931
```

実装時は、桁数を先に検証し、入力のチェックデジットを除外してから計算します。数値型へ変換すると先頭ゼロを失うため、必ず文字列で処理します。

### 6.2 ISBN-10

10桁を左から重み`10,9,8,...,1`で掛け、合計が11の倍数になるようにします。最後の値10は`X`で表示します。

```text
Σ(d_i × (11-i)) mod 11 = 0
```

### 6.3 ISSN

先頭7桁を左から重み`8,7,6,5,4,3,2`で掛けます。合計の11の補数を8桁目とし、10なら`X`、11なら`0`です。

### 6.4 Damm、Luhn、独自チェック

受付番号・POS内部コード・決済トークン等には、GS1モジュラス10以外のアルゴリズム（Damm、Luhn、Mod 11等）を採用できます。アルゴリズムが分からない数字列に対し、JANの計算を適用して「正しい」と判定してはいけません。名前空間ごとにアルゴリズムと入力範囲を定義します。

## 8. このPOSでの解釈方針

1. 入力を文字列として受け、Enter、CR/LF、NUL等の終端を正規化する。
2. AIM Symbology Identifierを保持できる場合は、payloadと一緒に保存する。
3. `0x1D`（GS）を含む場合はGS1 element string候補としてAIを左から解析する。
4. POS内部名前空間（例: `PS`で始まるCode 128 payload）を完全一致で解決する。
5. 数字列は、登録済み外部バーコードの完全一致、桁数、チェックデジットの順に候補化する。
6. GS1 AIの可変長項目は、次のAIまたはGS区切りがない限り勝手に分割しない。
7. 商品マスタにない外部コードの会社名・商品名・価格を推測して登録しない。検索候補はフィールド単位で明示採用する。
8. 1〜7桁の数字入力を現金預り金として扱う既存画面では、バーコード入力バッファと金額入力バッファを分ける。
9. QR/Data MatrixのpayloadをURL・JSON・GS1のどれとして扱うかは、リーダー情報または登録済み名前空間で確定する。

### 商品コードとして受け付ける際の注意

商品管理コードは先頭ゼロを保持した数字文字列として扱います。現在のPOS要件では、商品管理コードは数字のみ8桁以上ですが、これは「8桁以上の数字なら商品」と断定する規則ではありません。登録済み商品・外部バーコードの関連付け・チェックデジット・イベント設定を組み合わせて解決します。

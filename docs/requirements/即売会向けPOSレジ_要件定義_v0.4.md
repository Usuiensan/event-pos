# 即売会向けPOSレジスター 要件定義

- 文書版: v0.4
- 更新日: 2026年7月24日
- 主な更新: 商品バリエーション、セット販売、値引き、無料配布、取り置きおよび見本在庫の仕様を確定
- 対象: 即売会で使用するローカルWeb型POS
- 対象プリンター: Epson TM-T70II
- 印字言語: 日本語

## 1. 目的

本システムは、同人誌・グッズ等の即売会で、複数の販売担当者が同時に会計し、売上、在庫、年齢確認、レシート印刷、現金管理およびレジ締めを一元処理するためのPOSである。

会場内の専用Wi-Fi LANで動作し、レジ端末、顧客画面および管理端末は、iPad、PC、スマートフォン等のWebブラウザーからサーバーのIPアドレスへ接続する。インターネット接続やクラウドサービスは、通常の販売業務に必須としない。

## 2. 要件の要約

| 項目 | 要件 |
| --- | --- |
| 最大レジ数 | 基本4台 |
| 最大顧客画面数 | 4台 |
| 最大同時接続数 | 約10接続（レジ4、顧客画面4、管理端末2） |
| 会計処理量 | 通常想定10件/分、最大想定60件/分 |
| サーバーOS | WindowsおよびLinuxで同一機能を正式対応 |
| 操作端末 | iPad横画面およびPC横ウィンドウを基本とする |
| 接続方式 | 専用Wi-Fi LAN内でWebブラウザーからIPアドレスへ接続 |
| プリンター | Epson TM-T70IIを1台共有 |
| プリンター接続 | USBによるESC/POSバイナリ伝送 |
| 現金箱 | 原則レジ別。共通現金箱モードも用意 |
| 金種別計数 | 不要。実在高は総額入力 |
| スタッフ管理 | 個別IDで管理 |
| 管理者承認 | 承認済み責任者番号でログオンし、暗証番号を入力 |
| 外部決済端末 | POSとは直接接続しない |
| 数字列の自動判定 | 8桁以上は商品コード、1～7桁は預り金 |
| 入力モード | 高速モードのみ。小計操作を必須とする厳格モードは設けない |
| 商品バリエーション | 商品コードが異なれば別商品、同一なら同一商品として扱う |
| セット販売 | 複数商品を一括登録する、在庫を持たないショートカット商品で対応 |
| まとめ値引き | 対象商品コード、必要数量および適用上限に基づき自動適用 |
| 無料配布 | 売上ではなく、理由付きの在庫減として記録 |
| 取り置き | イベント終了締め時に未解決分を一覧化 |
| 見本在庫 | 通常在庫へ戻入れ可能。販売も可能 |
| データ閲覧 | 全スタッフが閲覧可能 |
| データ削除 | アプリケーションからは原則不可 |
| 印字言語 | 日本語のみ |

## 3. システム構成

### 3.1 基本構成

POSサーバー1台が、次の機能を一元管理する。

- Web画面の配信
- 認証および権限管理
- 商品、在庫、取引、支払および監査データの管理
- レジ、顧客画面および管理端末間の状態同期
- Epson TM-T70IIへの印刷
- キャッシュドロアー制御
- CSV出力およびバックアップ

各ブラウザー端末からプリンターへ直接印刷してはならない。すべての印刷依頼をPOSサーバー上の印刷キューへ登録し、1件ずつ直列処理する。

### 3.2 端末の役割

| 端末 | 主な機能 |
| --- | --- |
| レジ端末 | 商品登録、数量変更、会計、取消、返品、再印刷、担当者ログオン |
| 顧客画面 | 登録商品、数量、単価、小計、合計、R18確認、会計完了の表示 |
| 管理端末 | 商品・在庫・イベント設定、レジ状態確認、責任者操作、締め、CSV出力 |

顧客画面は特定のレジへ割り当てる。顧客画面がないレジでも会計できるものとする。顧客画面の切断はレジ側へ警告するが、顧客操作を必要としない会計まで停止させない。

### 3.3 サーバーOS

WindowsおよびLinuxを正式対応対象とし、次の機能差を設けない。

- POS本体の機能
- データベースの構造
- Epson TM-T70IIへの印刷
- プリンター状態取得
- キャッシュドロアー制御
- 自動起動
- CSV出力、バックアップおよび復旧

OS固有処理はプリンター接続層とサービス管理層へ限定し、会計ロジックから分離する。Windows専用ドライバーだけに依存せず、両OSでUSBへESC/POSバイナリを伝送できる方式を基本とする。

### 3.4 サーバーハードウェア

Raspberry Pi等の低消費電力Linux機、Windows対応の小型x86 PC、既存ノートPCを候補とする。

正式にWindowsとLinuxの双方へ対応するため、ソフトウェアは特定のCPUアーキテクチャへ依存させない。Raspberry Piを採用する場合はmicroSD単独運用を避け、USB SSD等の耐障害性が比較的高いストレージを使用する。

## 4. 性能・同時実行

### 4.1 想定負荷

- 最大同時接続数: 約10
- 通常想定: 1分当たり10会計
- 最大想定: 1分当たり60会計

最大想定の60会計/分は、平均して1秒に1件の売上確定要求に相当する。印刷はプリンター1台で直列処理されるため、会計確定処理と印刷完了を分離する。

### 4.2 必須性能要件

- 売上確定、支払登録、在庫減算および監査記録を1つのデータベーストランザクションとして処理する。
- 印刷待ちが発生しても、データベースの会計確定処理を不必要に停止させない。
- 同じ確定要求が再送されても、取引を1回だけ作成する。
- Enterキー連打、ボタン連打、通信再送による二重売上と二重印刷を防止する。
- 最後の1点を複数レジが同時登録した場合、在庫を不整合にしない。
- レジ画面は、会計が確定したのか、印刷だけが待機または失敗しているのかを区別して表示する。

性能試験では、60会計/分の確定要求を一定時間連続して与え、取引欠落、重複、在庫不整合および印刷ジョブ混線がないことを確認する。

## 5. 認証・権限・責任者承認

### 5.1 スタッフ認証

スタッフは個別IDで管理する。利用可能なログオン方式は次のとおりとする。

スタッフIDはどのような方式でもよいが入力上の利便として数字3桁の責任者番号をスタッフに割り当て普段は用いることにする。責任者番号に対応するスタッフが変更になっても良い。

- 3桁の責任者番号
- ログイン用バーコード
- 責任者番号と暗証番号の組合せ

スタッフIDは、取引、取消、返品、値引き、在庫調整、R18確認、再印刷および締め操作へ記録する。レシートに印字するのは「責任者番号」

### 5.2 権限

最低限、次の権限区分を設ける。

| 権限 | 主な操作 |
| --- | --- |
| 販売担当者 | 通常会計、未確定取引の取消、売上・在庫の閲覧 |
| 責任者 | 返品、確定済み取引の取消、任意値引き、在庫調整、再印刷、締め |
| システム管理者 | イベント設定、スタッフ設定、データ出力、復旧操作 |

### 5.3 管理者操作の承認

管理者操作は、事前承認済みの責任者番号でログオンしたうえで、暗証番号を入力して承認する。

承認記録には、対象操作、対象取引、実行者ID、承認者ID、日時、端末および理由を保存する。同一人物が実行と承認を兼ねることを許可するかはイベント設定とする。

## 6. 商品・価格・在庫

### 6.1 商品マスター

商品には最低限、次の情報を持たせる。

- 商品ID
- 商品名
- レジ用短縮名
- 価格
- 税率および税区分
- カテゴリ
- 表示順
- R18対象の有無
- 在庫管理対象の有無
- 販売中、売切れ、頒布停止等の状態

商品コードは数字のみの8桁以上とする。8桁未満の商品コードは、商品マスターの画面入力、CSV取込みおよびAPI登録のすべてで拒否する。EAN-8は8桁のまま保持し、先頭のゼロを削除しない。

商品コードは文字列として保存し、金額や連番として扱わない。同一の商品コードを複数の商品へ割り当てることはできない。

過去取引には現在の商品マスターを参照させず、取引時点の商品名、単価、税率および値引額を保存する。

### 6.2 在庫

次の在庫移動を区別して記録できるものとする。

- 開始在庫
- 追加入庫
- 販売
- 未確定取引の取消
- 確定済み取引の取消または返品
- 破損
- 無料配布
- 取り置き
- 見本
- 手動調整

在庫は原則として会計確定時に減算する。取消・返品時は元記録を削除せず、逆方向の在庫移動を追加する。

### 6.3 商品バリエーション

色、サイズ、版等の違いを別商品として扱うかは、サークル側の商品コード設計に委ねる。

- 商品コードが異なる場合は、別の商品として扱い、売上および在庫を個別に集計する。
- 商品コードが同一の場合は、色、サイズ、版等が異なっていても同一商品として扱う。
- POSは、同一商品コード内の内訳を推測または追加管理しない。
- バリエーション間の在庫振替は、別の商品コードを使用している場合に限り、理由付きの在庫調整として記録する。

### 6.4 セット販売用ショートカット

複数の商品コードを一度に商品登録するため、タッチパネルから操作できる「セット販売用ショートカット商品」を設定できるものとする。

- ショートカット商品は、複数の構成商品コードと各数量を持つ。
- ショートカット商品自体には物理的な実体および在庫を持たせない。
- ショートカットを押すと、構成商品を現在の取引へ一括登録する。
- 売上、税および在庫は、実体のある構成商品に基づいて処理する。
- ショートカットの使用回数またはセット頒布数を、構成商品の販売数とは別の集計値として記録できる。
- 構成商品のいずれかが売切れ、頒布停止、年齢確認未完了その他の理由で登録できない場合は、構成商品を一部だけ登録せず、ショートカット全体をエラーとする。
- ショートカットの内容を変更しても、確定済み取引には取引時点の構成を保存する。

セット固有価格を実現する場合は、構成商品を一括登録した後に、6.5の自動値引きを適用する。

### 6.5 まとめ値引き

特定の商品コードの組合せおよび数量条件を満たした場合、まとめ値引きを自動適用する。

値引きルールには最低限、次を設定できるものとする。

- ルールIDおよび名称
- 対象の商品コード
- 各商品の必要数量
- 値引額または値引率
- 1取引内で値引対象とする数量または適用回数の上限
- 有効・無効

商品追加、数量変更、行取消またはセットショートカット登録のたびに条件を再計算する。条件を満たさなくなった自動値引きは自動で解除する。

複数の値引きルールが同時に成立する場合の優先順位、重複適用および最も有利な組合せを選ぶかどうかは、ルール設定で明示する。設定が競合して適用結果を一意に決められない場合は、黙って一部を適用せず、商品設定エラーとして管理画面へ表示する。

取引には、適用したルールID、対象行、対象数量、値引額および適用回数を保存する。確定済み取引は、その後のルール変更によって再計算しない。

### 6.6 任意値引き

任意値引きの上限および責任者承認の要否は、サークル側がイベント設定で決定する。

- POSの値引きエンジンには固定の金額上限または率上限を設けない。
- イベント設定により、上限なし、金額上限、率上限または責任者承認必須を選択できる。
- 100%値引きにより取引合計を0円とすることを許容する。
- 値引きによって商品行または取引合計を負数にはしない。顧客への金銭支払が必要な処理は、値引きではなく返品・返金として扱う。
- 任意値引きには理由を入力でき、イベント設定で理由入力を必須にできる。
- 実行者、承認者、対象商品または取引、値引前後の金額、理由および日時を監査ログへ保存する。

### 6.7 無料配布

無料配布した商品は、販売可能在庫から減算する。ただし、通常売上、0円売上または値引販売としては計上せず、「無料配布」という独立した在庫移動として記録する。

無料配布記録には、商品コード、数量、日時、担当者、イベント、理由区分および任意メモを保存する。理由区分は、見本品、試供品、宣伝配布、購入特典、その他等を設定可能とする。

売上集計、税率別売上および支払集計からは除外し、在庫移動CSVおよび無料配布CSVへ出力する。会計処理に必要な場合に備え、商品マスターの原価、配布時点の原価および理由区分を出力できるデータ構造とする。

対価を受け取らない試供品・見本品等は、消費税上、原則として対価を得て行う取引には当たらない。一方、所得税・法人税上の費用区分は、配布の相手方、目的、事業形態等で異なり得る。そのため、POSは無料配布を一律に課税売上、広告宣伝費、交際費または寄附金へ確定せず、会計処理に必要な事実を記録・出力する。

無料配布の取消は元記録を削除せず、逆方向の在庫移動を追加する。

### 6.8 取り置き

取り置きは、販売可能在庫と区別して数量を確保する在庫状態として扱う。

- 取り置き登録時に、商品コード、数量、登録日時、担当者、識別用名称または任意メモを記録する。
- 取り置き中の数量は、通常販売で利用できる在庫から除外する。
- 受取時は、取り置きから対象商品を会計へ移し、会計確定時に販売として記録する。
- 解除時は、取り置き数量を販売可能在庫へ戻す。
- 受取および解除は元の取り置き記録へ履歴として追加し、担当者と日時を記録する。
- イベント終了締めまでに受取または解除されていない取り置きを一覧化する。
- 一覧化後の販売、持越し、解除その他の処理はサークル側の判断に委ねる。
- 未解決の取り置きが存在しても締めを禁止しないが、警告を表示し、締め記録へ件数と数量、未解決の各取置登録データを印刷・保存する。

### 6.9 見本在庫

見本に使用する商品は、販売可能在庫と同一管理する。

- 見本在庫を販売できる。
- 見本を販売する場合は、通常販売する。
- 汚損等により販売不能となった見本は、破損または廃棄等の在庫移動へ振り替える。

## 7. 会計

### 7.1 基本フロー

1. 担当者がログオンする。
2. 商品またはセット販売用ショートカットを登録し、必要に応じて数量変更、行取消または全取消を行う。
3. 条件に該当するまとめ値引きを自動計算し、任意値引きがあれば登録する。
4. R18商品がある場合、指定された年齢確認を完了する。
5. 現金預り金を入力するか、支払方法と金額を登録する。
6. サーバーが売上、支払、在庫および監査記録を確定し、取引番号を発行する。
7. 印刷ジョブを登録する。
8. 顧客画面に会計完了を表示した後、待機画面へ戻す。

### 7.2 釣り銭計算省略

イベントまたはレジ単位で、釣り銭計算省略モードを有効にできるものとする。

- Enterキーまたは「現計」ボタンで現金売上を確定する。
- 受取額および釣り銭は未入力として保存する。
- 売上金額のみを現金実績へ加算する。
- 画面上に「釣り銭計算なし」を常時表示する。
- 通常の預かり金・釣り銭計算へ即時切り替えられる。
- Enterキー押下を主要操作として設計する。

### 7.3 バーコードリーダーおよび数字入力の自動判定

バーコードリーダーは、読み取った文字列をキーボード入力として送信し、末尾にEnterキーを送るキーボード模擬型を使用する。通常の商品登録画面では、数字列の桁数によって入力の意味を自動判定する。

| 入力 | 処理 |
| --- | --- |
| 8桁以上＋Enter | 商品コードとして検索し、該当商品を1点登録 |
| 1～7桁＋Enter | 現金預り金として処理 |
| Enterのみ | 釣り銭計算省略が有効な場合、現金ちょうどとして会計確定 |
| 数字以外を含む入力＋Enter | エラー |

次の規則を必須とする。

- 桁数による自動判定を行う「高速モード」だけを実装する。
- 「小計」を押してから預り金を入力させるモードは設けない。
- 8桁未満の商品コードは一切許容しない。
- 8桁以上の数字列を預り金として解釈する例外操作は設けない。
- 1回の会計合計および1回の預り金入力は7桁、9,999,999円を上限とする。
- 金額の先頭のゼロは数値化するときに除去する。商品コードの先頭のゼロは保持する。
- 商品が1点も登録されていない状態では、1～7桁＋Enterを預り金として受け付けない。
- 商品コードが商品マスターに存在しない場合は、金額入力へ読み替えず商品未登録エラーとする。
- バーコードリーダーの入力速度やキー間隔による判定は行わない。
- 会計確定処理中、印刷待ちへの遷移中および次取引への初期化中は、重複するEnterを無視する。

預り金が会計合計以上の場合は、現金会計を確定し、預り金から会計合計を差し引いた額を釣り銭として表示・保存する。預り金が会計合計未満の場合は「預り金不足」としてエラー表示し、会計を確定せず、現金支払明細も登録しない。この入力を分割現金や併用払いの開始として自動解釈してはならない。

商品登録と預り金入力は、画面表示およびブラウザー音声を明確に分ける。入力バッファーはEnterによる処理完了後またはエラー確認後に消去し、前回の数字列を次の入力へ持ち越さない。

### 7.4 支払方法

外部決済端末とは直接接続しない。担当者が外部端末で決済完了を確認し、POSへ「支払方法」と「金額」を登録する。

例:

- 現金 2,000円
- クレジットカード 3,000円
- 交通系IC 1,500円
- QRコード決済 2,500円

### 7.5 併用払い

1件の取引に複数の支払明細を登録できるデータ構造とする。

- 外部決済と残額現金の組合せは常に許可する。
- 外部決済を複数併用する組合せも、設定上は許可できるものとする。
- 支払合計が取引合計と一致するまで会計を確定できない。
- 外部決済端末との自動照合は行わない。
- 外部決済の承認番号等は必須としないが、任意の照合メモ欄を設けることはできる。

複雑な併用払いは操作負荷が高いため、イベント設定で許可する支払方法と組合せを制限できるものとする。

外部決済額の登録後に未払い残額がある場合は、支払方法選択画面へ戻る。残額を現金で支払う場合は、次の順序で操作する。

1. 支払方法選択画面で「現金」を押す。
2. 1～7桁の現金預り金を入力する。
3. Enterキーを押す。
4. 入力額が未払い残額以上なら、現金支払額を残額分として登録し、超過分を釣り銭として表示・保存して会計を確定する。
5. 入力額が未払い残額未満なら「預り金不足」としてエラー表示し、現金支払明細を登録しない。

「現金」を押した後の入力状態では、1～7桁＋Enterだけを現金預り金として受け付ける。8桁以上の入力は金額超過エラーとし、商品コードとして登録しない。商品を追加する場合は、支払入力を取り消して商品登録画面へ明示的に戻る。

外部決済の登録額が会計合計を超える場合は、POS上では釣り銭を計算せずエラーとする。キャッシュレス決済額の修正または外部決済端末側の取消を行った後で再入力する。

### 7.6 外部決済の取消

POS上の取消と外部決済端末上の取消は別操作である。POSでキャッシュレス売上を取り消す際は、外部端末側の取消・返金確認を担当者へ表示し、その完了結果を記録する。

## 8. R18頒布・年齢確認

### 8.1 基本方針

R18確認方法はイベントごとに設定する。POSは確認手順の実施と記録を支援するが、法令、イベント規約またはサークル方針上の十分性を自動判定しない。

### 8.2 対応する確認方式

| 方式 | 操作 | 保存する情報 |
| --- | --- | --- |
| 自己申告 | 顧客が「18歳以上ですか？」に対して「はい」を押す  必ず容貌確認または身分証目視と併用| 方式、結果、取引ID、端末、日時 |
| 容貌確認 | 担当者が外見による確認済みを入力 | 方式、結果、確認者ID、取引ID、日時 |
| 身分証目視 | 担当者が身分証を目視し、満18歳以上であることを入力 | 方式、結果、確認者ID、取引ID、日時 |

身分証の画像、種類、番号、氏名、住所、生年月日その他の身分証記載事項は保存しない。

### 8.3 確認不能時

年齢確認ができない場合、当該R18商品を現在の取引から取り消す。担当者は、確認条件を満たした後で商品を再登録できる。

R18商品以外は、そのまま会計を継続できる。

### 8.4 記録保存

年齢確認記録は取引に紐付け、売上データと同じ期間保存する。確認記録を訂正する場合は元記録を削除せず、取消情報と訂正後の記録を追加する。

## 9. 顧客画面

顧客画面には次の情報を表示する。

- 現在の商品名
- 数量
- 単価
- 小計
- 値引き
- 無料配布
- 取り置きの登録、受取および解除
- 合計
- R18自己申告画面
- 支払待ち、処理中、会計完了、確認不能等の状態

顧客画面から商品、数量、価格または支払を変更できない。入力可能なのは、年齢確認等の明示的に許可された確認操作だけとする。

取引終了後は商品名、金額および年齢確認結果を残さず、一定時間後に待機画面へ戻す。

## 10. プリンター

### 10.1 基本仕様

| 項目 | 仕様 |
| --- | --- |
| 型番 | Epson TM-T70II |
| 紙幅仕様 | 58 mm仕様 |
| 使用ロール紙幅 | 57.5 ± 0.5 mm |
| 最大印字幅 | 52 mm、416ドット（203 dpi） |
| 接続 | POSサーバーへUSB接続 |
| 伝送 | ESC/POSバイナリ |
| 共有方法 | サーバー上の単一印刷キュー |
| 台数 | 1台 |
| 印字言語 | 日本語 |
| カット | オートカッターを使用 |
| キャッシュドロアー | 使用可能性あり |
| ブザー | 原則使用しない |
| 利用者への通知 | レジ側ブラウザーで音声を再生 |

本システムではTM-T70IIの58 mm仕様だけを正式対応対象とする。レシートレイアウトは、用紙幅57.5 ± 0.5 mm、最大印字幅52 mm・416ドットを上限として設計する。

添付コマンド資料の `!width 384` は、最大印字幅416ドットの全域を使わず、左右の余白を確保した印字領域の指定として扱う。レシートテンプレートでは416ドットを物理上限、384ドットを標準の内容幅とする。

### 10.2 印刷キュー

印刷ジョブは次の状態を持つ。

- 待機
- 送信中
- 完了
- 失敗
- 再試行待ち
- 取消

ジョブIDと取引IDを分け、初回印刷と再印刷を識別する。再印刷レシートには「再印刷」、再印刷回数および元取引番号を印字する。

各ジョブの先頭でプリンターを初期化し、文字揃え、太字、下線、倍率等の状態を標準へ戻す。紙送りとカットはジョブ末尾で実行し、複数レジから直接送信しない。

### 10.3 状態取得

TM-T70IIのESC/POSステータス機能を用い、可能な範囲で次の状態を取得する。

- 接続・応答の有無
- オンライン・オフライン
- ロール紙カバー開
- 用紙切れ
- 復帰可能エラー
- 復帰不可能エラー

USBクラス、OS、USBライブラリーおよびプリンター設定によって取得方法が異なる可能性があるため、WindowsとLinuxの双方で実機試験を行う。取得できない状態は推測せず、「状態不明」と表示する。

### 10.4 キャッシュドロアー

TM-T70IIのドロアーキックコネクターとESC/POSのパルス出力により制御する。接続するドロアーに応じて駆動ピンとパルス幅を設定する。

ドロアーを開く条件は次を基本とする。

- 現金会計の確定
- 釣り銭準備
- 責任者による点検

キャッシュレスのみの会計では原則として開かない。任意のドロアー開放は責任者操作とし、操作履歴を残す。

### 10.5 ブザーおよびブラウザー音声

プリンター内蔵または外付けブザーは原則使用しない。次の通知はレジ側ブラウザーで音声再生する。

- R18確認が必要
- 支払額が不足
- 会計確定
- プリンター異常
- 顧客画面切断
- 責任者承認が必要

ブラウザーの自動再生制限に対応するため、ログオン後の初回操作で音声利用を有効化し、開始前にテスト音を再生する。音声だけに依存せず、画面表示と併用する。

### 10.6 添付コマンド資料の扱い

添付の `discord用esc-pos-command.txt` は、生のESC/POSバイト列一覧ではなく、既存Discordプリンターボットが解釈する操作コマンドの一覧である。

POSでは、次のいずれかの方法で利用する。

1. 既存ボットのコマンド解析部分をプリンター層として再利用する。
2. 各コマンドをPOS内部のレシート描画命令へ対応付け、最終的にESC/POSバイナリへ変換する。

`!cut partial3`、`!drawer`および`!buzzer`の正確な引数と実機挙動は、既存実装と実機で確認する。

## 11. レシート・税

### 11.1 レシート記載項目

最低限、次の項目を印字する。

- サークル名または発行者名
- イベント名
- 取引日時
- 取引番号
- レジ番号
- 担当者名
- 商品名
- 数量
- 単価
- 値引き
- 税率別の税込合計額
- 適用税率
- 税率別の消費税額
- 合計額
- 支払方法別の金額
- 受取額および釣り銭（入力した場合）
- 返品条件または問い合わせ案内

### 11.2 適格請求書に関する扱い

現時点では適格請求書発行事業者の登録番号を印字しない。この場合、国税庁が定める「適格簡易請求書」には該当しない。

本システムは、登録番号がなくても税率別の税込合計額、適用税率および税率別消費税額を表示できる通常レシートを発行する。将来、登録番号を設定した場合は、簡易適格請求書に必要な記載事項を満たす様式へ切り替えられるものとする。

消費税額の端数処理は、1枚のレシートにつき税率ごとに1回行い、処理方法をイベント設定として固定する。

## 12. 取消・返品・返金

### 12.1 基本方針

返品の可否および条件はサークル側の判断に委ねる。POSの機能としては、確定済み取引に対する取消・返品を常に実行可能とする。

### 12.2 データ処理

- 未確定取引の行取消・全取消と、確定済み取引の取消・返品を区別する。
- 確定済み取引を上書きまたは削除しない。
- 元取引を参照する負の取引または相殺取引を作成する。
- 返品商品を在庫へ戻すか、破損等として戻さないかを選択できる。
- 返品理由、実行者、承認者、日時および端末を保存する。
- キャッシュレス返金では、外部決済端末側の処理結果を記録する。

## 13. 現金管理・レジ締め

### 13.1 現金箱

現金箱はレジごとに分けることを原則とする。イベント設定により、複数レジで共通の現金箱を使用できる。

| モード | 締め方法 |
| --- | --- |
| レジ別現金箱 | レジごとに準備金、理論現金、実在高および過不足を算出 |
| 共通現金箱 | 個別レジではなく、現金箱単位またはイベント全体で算出 |

### 13.2 金種別計数

金種別の枚数入力は不要とする。開始時の釣り銭準備金および終了時の実在高を総額で入力する。

理論現金は次の式で算出する。

```text
理論現金 = 釣り銭準備金 + 現金売上 - 現金返品 - 出金 + 入金
現金過不足 = 実在高 - 理論現金
```

### 13.3 締め確認

締め時に次を確認する。

- 未完了取引
- 印刷失敗または印刷待ち
- 未処理の取消・返品
- 現金の理論額、実在高および過不足
- 商品別の理論在庫および実棚差異
- 支払方法別売上
- レジ別・担当者別売上

締め後のデータは読み取り専用とする。再開または修正には責任者承認と理由入力を必要とする。

## 14. データ保存・閲覧・削除

### 14.1 閲覧

売上、在庫および監査データは全スタッフが閲覧できる。個人情報を保存しない設計を前提とする。

### 14.2 削除

アプリケーションから売上、在庫および監査データを削除する機能は設けない。訂正は元データの削除ではなく、取消・返品・調整記録の追加で行う。

### 14.3 保存期間

具体的な保存年数は未確定である。イベントまたは運営主体の会計・税務上必要な期間を別途決定し、売上、在庫、R18確認および監査データに同じ保存方針を適用する。

### 14.4 CSVおよびサーバー停止後の読取り

次のCSVを出力できるものとする。

- 売上明細
- 支払明細
- 商品別販売
- 在庫移動
- 無料配布
- 取り置き
- 見本在庫移動
- 現金締め
- R18確認
- 取消・返品
- 監査ログ

CSVは通常運用中に管理画面から出力できるものとする。POSサーバーを停止した後でもデータを読み取れる運用を想定するが、データベースファイルを直接CSVとして扱ってはならない。終了時に自動生成したCSVまたは専用のオフライン出力手順を使用する。

## 15. 画面・操作性

### 15.1 優先画面

1. iPad横画面
2. PCの横長ブラウザーウィンドウ
3. スマートフォン

スマートフォンは接続可能とするが、主たるレジ操作端末としての最適化優先度は低い。

### 15.2 キーボード操作

多少の訓練を受けた熟練者が高速に操作することを前提とし、キーボード操作を重要要件とする。

最低限、次の操作へショートカットを割り当てる。

- 商品選択
- 数量変更
- 行取消
- 全取消
- 現金会計
- 釣り銭計算省略での確定
- 支払方法選択
- R18確認
- 責任者呼出し
- 次の取引

Enterキーの意味は画面状態ごとに一意とし、誤確定を防ぐ。主要操作はマウス、タッチおよびキーボードのいずれでも実行できるものとする。

通常の商品登録画面では、8桁以上＋Enterを商品コード、1～7桁＋Enterを現金預り金として固定する。支払方法選択後の金額入力画面では、画面上で選択した支払方法に対する金額として処理し、商品登録へ読み替えない。

### 15.3 アクセシビリティ

アクセシビリティの優先度は高速操作より若干低いが、次の最低限の要件は満たす。

- 文字と背景の十分なコントラスト
- 色だけに依存しない警告表示
- 音声だけに依存しない通知
- キーボードフォーカスの可視化
- タッチ対象の十分な大きさ
- 拡大表示で主要操作が欠落しないこと

## 16. 障害対応

| 障害 | 動作 |
| --- | --- |
| プリンター紙切れ | 売上確定済みと印刷待ちを分けて表示し、紙交換後に対象ジョブを再印刷 |
| プリンター切断 | 印刷キューを停止し、ブラウザーの画面と音声で警告 |
| 顧客画面切断 | レジ側へ警告。顧客操作が不要な会計は継続可能 |
| レジ端末切断 | 確定結果を推測せず、再接続後に取引IDで照会 |
| サーバー再起動 | DBと印刷キューを復元し、全端末を再接続 |
| ルーター障害 | 予備ルーターまたは保存済み設定から復旧 |
| 停電 | バッテリーで継続または安全停止し、再起動後に整合性確認 |

OSの自動更新、自動再起動、スリープおよびUSB省電力によってイベント中に停止しない設定とする。

## 17. 監査

次の操作を監査ログへ保存する。

- ログオン、ログオフ、担当者交代
- 会計確定
- 未確定取引の取消
- 確定済み取引の取消・返品
- 値引き
- 在庫調整
- R18確認
- 責任者承認
- ドロアー開放
- 再印刷
- イベント設定変更
- 締めおよび締め取消
- CSV出力

監査ログには、日時、担当者ID、承認者ID、端末、操作、対象ID、変更前後および理由を記録する。監査ログ自体の編集・削除機能は設けない。

## 18. 受入試験

### 18.1 会計・同時処理

- 4台のレジ、4台の顧客画面および2台の管理端末を同時接続できる。
- 60会計/分の要求を処理して、売上と在庫に欠落・重複がない。
- 最後の1点を複数レジで同時販売しても在庫が不整合にならない。
- 商品コードが異なるバリエーションは別商品、同じ商品コードは同一商品として集計される。
- セット販売用ショートカットにより構成商品を一括登録し、構成商品の在庫と売上だけが計上される。
- セット構成の一部を登録できない場合、構成商品が一部だけ取引へ残らない。
- まとめ値引きの条件成立、数量上限、条件不成立への変化に応じて値引きが自動で適用・解除される。
- 任意値引きの上限および承認要否がイベント設定どおりに動作する。
- 100%値引きは可能だが、商品行および取引合計は負数にならない。
- Enterキー連打、ボタン連打、通信再送で二重確定されない。
- 8桁以上＋Enterで商品を登録し、1～7桁＋Enterで現金預り金を処理できる。
- 8桁未満の商品コードを、画面、CSVおよびAPIのいずれからも登録できない。
- 8桁以上の数字列を預り金として登録できない。
- 商品がない状態で1～7桁＋Enterを押しても、現金会計が開始されない。
- 未登録の商品コードを預り金として読み替えない。
- 預り金が会計合計未満の場合、「預り金不足」を表示し、取引と現金支払明細を確定しない。
- 外部決済後に残額がある場合、「現金」選択、1～7桁、Enterの順で預り金を処理できる。
- 併用払いの現金預り金が残額未満の場合、エラーとなり現金支払明細を追加しない。
- 併用払いの現金預り金が残額を超える場合、残額分を現金支払として登録し、超過分を釣り銭として記録する。

### 18.2 印刷

- WindowsとLinuxの双方からTM-T70IIへ同じ内容を印刷できる。
- 4台のレジが同時に印刷してもレシートが混線しない。
- 紙切れ、カバー開、USB切断を検出または状態不明として適切に表示できる。
- 障害復旧後、対象取引だけを再印刷できる。
- 再印刷によって売上が再計上されない。
- カットおよびキャッシュドロアーが設定どおり動作する。

### 18.3 R18確認

- 設定された確認を完了しない限りR18商品を含む取引を確定できない。
- 確認不能時にR18商品だけを取り消し、再登録できる。
- 身分証の個別情報がデータベース、ログ、CSVおよびレシートへ保存されない。

### 18.4 締め・監査

- レジ別現金箱と共通現金箱の双方で理論現金と過不足を算出できる。
- 金種別入力をせず、総額だけで締められる。
- 取消、返品、在庫調整および締め修正が元記録を消さない。
- 無料配布が売上・支払・税率別売上へ混入せず、在庫減と無料配布記録に反映される。
- 取り置きの登録、受取および解除に応じて、販売可能在庫と取り置き数量が整合する。
- 締め時に未解決の取り置きが一覧化され、締め記録へ件数と数量が残る。
- 見本在庫を販売可能在庫へ戻し、または見本状態から販売できる。
- サーバー再起動後も売上、在庫および印刷キューが整合する。

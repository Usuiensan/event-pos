event-pos UI配色提案（ブランド色 #c0ffee）
================================================

作成日: 2026-08-04
対象: apps/register-web の全画面
位置づけ: 実装前の配色設計案。現行CSSへの置換はこの案の確認後に行う。

1. 結論
-------

ブランド色は #c0ffee とする。ただしこれは非常に明るい色なので、白背景上の本文色や、白文字を置く主ボタンの背景には使わない。

- #c0ffee: ブランド面、選択面、見出し帯、ロゴ背景、合計欄の強調に使う。
- #062f3d: ブランド色上の文字、濃いブランドヘッダー、ブランドの主操作ボタンに使う。
- #0b6070: 白背景上でも十分に読めるブランド系の主操作色に使う。
- 肯定的操作: 緑。確定、完了、確認済みを表す。
- 否定的操作: マゼンタ系。取消、返品、反転など「元の状態を取り消す」操作を表す。
- 危険操作: 赤。削除、営業終了、精算確定など、取り消しに責任者確認が必要な操作を表す。
- 警告: アンバー。注意、差異、年齢確認待ち、処理待ちを表す。
- 結果不明: 紫。印刷結果不明や外部状態不明を、成功にも失敗にも読み替えない。
- 情報・接続: 青緑。検索、接続中、説明、補助情報を表す。

操作の意味と状態の意味を混ぜない。たとえば、緑は「送信ボタンだから緑」ではなく、確定済み・成功・確認済みの表示に優先して使う。送信前の主ボタンはブランド色とする。

2. 根拠と適用基準
------------------

W3C WCAG 2.2 の次の基準を採用する。

- 色だけを情報伝達の手段にしない。色に加えて、日本語ラベル、アイコン、形、線、配置を併用する。
- 通常サイズの本文・ボタン文字は、背景とのコントラスト比 4.5:1 以上を目標とする。
- ボタンの境界、入力欄、選択状態、フォーカスリングなど意味のある非テキスト要素は、隣接色との差 3:1 以上を目標とする。
- キーボードフォーカスは常に見えるようにし、色だけでなく 2px の輪郭で示す。
- 非活性要素は状態を伝える目的のコントラスト判定から除外されるが、実運用では無効理由の文言を近接表示する。

GOV.UK Design System の機能色の考え方も採用する。色を単なる装飾ではなく、brand、success、error、focus など固定された役割に割り当て、同じ役割を画面ごとに別色へ変えない。

参照:
- https://www.w3.org/TR/WCAG22/
- https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html
- https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast
- https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html
- https://design-system.service.gov.uk/styles/colour/

----------------------

補足:

- #c0ffee を白文字のボタン背景にしない。#c0ffee を背景にする場合は #062f3d の文字を使う。
- #98a2b3 は境界専用。本文、ラベル、状態文字には使わない。
- 淡色面の上の状態文字は、各行の濃色トークンを使う。
- ブランド色は操作の成功を意味しない。ブランドの主ボタンを押した後、結果が成功したときだけ positive を表示する。
- 部門・商品タブの色は分類用に限定し、success / danger / unknown の意味を持たせない。

4. 操作・状態の色ルール
------------------------

操作種別              背景/文字                              用途例
------------------------------------------------------------------------------------------------------
通常の主操作          #0b6070 / #ffffff                     会計へ進む、検索、保存、候補を採用
ブランド強調          #c0ffee / #062f3d                     選択中、現在のタブ、ブランド見出し
肯定的操作            #0f7a52 / #ffffff                     支払確定、開局確認、確認できた、完了
否定的操作            #9f1239 / #ffffff                     取消、返品、返金、元に戻す、登録中止
危険操作              #b42318 / #ffffff                     削除、営業終了、精算確定、全消去
警告・保留            #b54708 / #ffffff                     年齢確認待ち、差異あり、送信中、再確認
結果不明              #6941c6 / #ffffff                     印刷結果不明、外部決済結果不明、照会待ち
中立・戻る            #e7ebef / #27333e                     戻る、閉じる、キャンセル、設定変更
無効                  #eef1f3 / #667085                     操作不可。近くに理由を表示

「戻る」「閉じる」は破壊しないため中立色とする。「取消」「返品」「返金」は既存記録を反転させる否定的操作としてマゼンタ系にする。「削除」「営業終了」「精算確定」は影響範囲が大きく、確認後に戻せない危険操作として赤にする。

すべての状態バッジは、色、ラベル、可能ならアイコンを組み合わせる。

- 成功: 「完了」「正常」「確認済み」＋チェックアイコン
- 警告: 「注意」「処理中」「差異あり」＋警告アイコン
- エラー: 「失敗」＋エラーアイコン＋原因と復旧方法
- 結果不明: 「結果不明」＋照会/虫眼鏡アイコン。自動再送しない

5. 画面別の適用案
------------------

5.1 起動画面（Launcher）

- 背景: #f8fafc。現行の青→緑グラデーションは状態を表さないため、薄いブランド面を使う単色またはごく弱いグラデーションへ整理する。
- POSマーク: 背景 #c0ffee、文字 #062f3d。ブランド色を最も分かりやすく見せる場所。
- レジ番号の選択中: 背景 #c0ffee、文字 #062f3d、2px #0b6070 の輪郭。「現在選択中」の文言も維持する。
- 店員側・顧客側・管理画面: 3色で意味を分けず、同じブランド系のカードを使う。カード内の見出し・説明・アイコンで役割を区別する。
- トレーニングモード: #6941c6 と #f4f3ff。通常業務と混同させない「本番DBへ書き込まない」モードとして紫を使う。
- 無効/読み込み中: グレー面＋「選択できません」を表示し、透明度だけで無効を示さない。

5.2 店員側レジ画面（登録・会計）

- ヘッダー: #062f3d、ブランドマーク/現在業務名を #c0ffee。担当者名、レジ番号、接続状態は白または状態色で表示する。
- 商品タブ: 通常は #e7ebef、選択中は #c0ffee＋#062f3d。部門色を使う場合もタブの分類表示だけに限定する。
- 商品ボタン: 白または淡い部門面。価格と商品名は #101828。商品ボタン自体に success/danger の意味を持たせない。
- 明細の選択行: #e7faff、2px #0b6070 の輪郭。登録直後の短いハイライトもブランド系にする。
- 取消済み明細: #fff1f2、#9f1239 のラベル「取消済み」、取り消し線。行を消して成功に見せない。
- 値引表示: #fff7ed、#b54708。値引前、値引額、値引後をラベルで分ける。
- 合計・小計: #c0ffee の面に #062f3d。金額の主役として目立たせるが、警告や確定済みとは解釈させない。
- 会計へ進む/支払方法: #0b6070 / 白。会計を確定する前の主操作なので brand-action とする。
- 支払確定: #0f7a52 / 白。確認モーダル内で1つだけ主ボタンとして表示する。
- 登録中止: #9f1239 または確認モーダル内で #b42318。単なる「戻る」と視覚的に分ける。
- 行操作の「数量変更」「売価変更」: 中立色または brand-action。取消だけ negative にする。
- ドロアー/現金管理入口: brand-action。現金操作の入口であり、直ちに現金確定する操作ではない。
- サインアウト/閉じる: 中立色。赤を使わない。

5.3 顧客側画面

- 背景と明細: #f8fafc / #ffffff。店員側の操作色を持ち込まず、読み取りを優先する。
- 明細の交互行: #ffffff と #e7faff 程度の弱い差にする。部門色や赤/緑を使わない。
- 合計欄: #c0ffee、文字 #062f3d。客が最も確認したい金額の場所としてブランドを使う。
- 値引: #fff7ed / #b54708。値引が適用されたことをラベルでも明示する。
- 年齢確認中: #fff7ed / #b54708、「店員確認中」。身分証情報は表示しない。
- 年齢確認済み: #ecfdf3 / #0f7a52、「確認済み」＋チェック。
- 客側スキップ: 通常時は表示しない。表示する場合は #b42318 の確認操作とし、待ち時間・理由を同じ画面に置く。
- 完了/待機: 完了は #ecfdf3、待機は中立色。次取引を success 色の大ボタンにしない。

5.4 サインオン・ライフサイクル画面

- ヘッダー/カードのブランド帯: #c0ffee / #062f3d。
- 責任者番号の入力フォーカス: #f59e0b の2px以上のリング。入力値そのものは #101828。
- サインオン送信: #0b6070 / 白。認証成功後の表示だけ #0f7a52。
- 接続中: #0f7a52。接続失敗: #b42318。取得不能: #6941c6「結果不明」または「状態を取得できません」。
- 戻る: 中立色。認証失敗の表示は赤文字だけにせず、原因と再入力方法を併記する。

5.5 業務メニュー

- モーダルの見出し: #062f3d、見出し内のブランドマーク/線は #c0ffee。
- 最もよく使う「現金管理・開局／点検／精算」入口: #0b6070 / 白。頻度を上げるため先頭配置と大きさでも強調する。
- 取り置き・受取会計、運用ダッシュボード、設定: 中立面または brand-action。赤・緑で入口の危険度を示さない。
- 全部返品: #9f1239。入口は negative、確定モーダルの「返金レシートを発行」は #b42318。
- 商品JSONインポート、再印刷: brand-action。処理結果は print status の色で別途表示する。
- 閉じる: 中立色。

5.6 現金管理・開局・点検・精算

- 画面枠と見出し: #062f3d / #c0ffee。現金管理の入口と画面をブランドで一貫させる。
- 理論現金・実在高: #ffffff / #101828。差額がある場合だけ差額欄を #fff7ed / #b54708 にする。
- 開局確認・中間点検確定: #0f7a52。成功結果は「開局済み」「点検済み」とラベル表示する。
- 入出金登録: brand-action。理由入力前に肯定色を付けない。
- 精算実行: #b42318。確認画面で営業日、cashbox、実在高、差異、翌日残しを表示してから確定する。
- 営業終了/閉局: #b42318。処理中は #b54708、完了後は #0f7a52。
- 精算済み再開: #b42318 の危険操作。責任者・理由入力が必要であることを色以外でも表示する。
- 入力エラー: #fef3f2 / #b42318。金額不足・過剰などの具体的な修正方法を添える。
- artifact生成待ち: #fff7ed / #b54708。精算成功とartifact成功を同じ緑で表示しない。

5.7 運用ダッシュボード

- ダッシュボード全体: 現行の濃い背景は維持可能だが、状態文字を明るくしすぎず、カードの背景と文字の組合せを固定する。代替案は #f8fafc の明るい背景。
- DB readiness 正常: #ecfdf3 / #0f7a52、「正常」。
- DB/PrinterHost/顧客画面の切断: #fef3f2 / #b42318、「切断」。
- PrinterHost 状態取得不能、印刷結果不明: #f4f3ff / #6941c6、「結果不明」。
- pending/retry/generating: #fff7ed / #b54708、「処理中」または「待機」。
- print job completed、artifact completed: #ecfdf3 / #0f7a52。
- holds の閉局 blocker: #fef3f2 / #b42318。確認が必要な取り置き: #fff7ed / #b54708。
- DB空き容量・成果物空き容量: 通常は中立、閾値超過時のみ warning。容量値の色だけでなく「残り○MB」を表示する。
- 各カードに状態ラベルを必ず出す。色付き点だけのインジケータにはしない。

5.8 返品・返金

- 画面の枠・見出し: #9f1239 系の negative。通常会計のブランド色と混同させない。
- 「元売上を全部返品」「レシートなし・例外返金」のモード選択: 通常は中立、選択中は #fff1f2 / #9f1239。
- 検索・対象選択: #0b6070 / 白。検索結果の「返品済み」は中立/無効面にし、再実行できないことを明示する。
- 返品内容・返金額入力: 通常の白面。入力エラーだけ #fef3f2 / #b42318。
- 「返金レシートを発行」: #b42318 / 白。確定前に元受付番号、商品、支払方法、返金額、在庫戻しを表示する。
- 完了: #ecfdf3 / #0f7a52。ただし「紙へ扱い者署名と理由を記載してください」は warning 面で近接表示する。
- 返品処理中: #fff7ed。外部決済の結果不明: #f4f3ff、「外部返金結果を確認してください」。成功と推測しない。

5.9 管理画面

- 管理画面の背景: #f8fafc、カード: #ffffff、本文: #101828。
- タブ: 通常は中立、現在タブは #c0ffee / #062f3d。タブ名を色だけで区別しない。
- 「商品マスタに追加」「保存確定」「候補の各フィールドを採用」: #0b6070 / 白。保存成功の通知は #0f7a52。
- 商品候補: #e7faff / #0b6070。候補は未確定であることを表示し、自動登録と見える緑色は使わない。
- 商品削除、選択商品の一括削除、営業開始後に許可されない変更: #b42318 / 白、確認モーダルを必須にする。
- 商品を外す、キャンセル、商品マスタへ戻る: 中立色。削除確定と同じ赤にしない。
- 販売中: #ecfdf3 / #0f7a52。販売停止: #eef1f3 / #667085。状態名を併記する。
- GS1/ISDN検索: #0b6070。根拠を開くリンクは brand-action。候補採用はフィールド単位で明示する。
- 未保存変更: #fff7ed / #b54708。「保存確定」までYAMLへ保存されないことを表示する。
- 管理者サインオン: ブランド帯 #c0ffee / #062f3d、送信 #0b6070、失敗 #b42318。

5.10 印刷状態・再印刷・バックアップ成果物

状態                  面/文字                              表示
------------------------------------------------------------------------------------------------------
completed             #ecfdf3 / #0f7a52                     完了・印字処理完了
sending/retry/pending #fff7ed / #b54708                     処理中・再試行待ち
failed                #fef3f2 / #b42318                     失敗・再送不可/要確認
unknown               #f4f3ff / #6941c6                     結果不明・実物確認が必要
canceled              #eef1f3 / #667085                     取消済み

- 「accepted bytes」と紙面の完成を同じ success 色にしない。transport状態と紙面確認を別の行で表示する。
- unknown は濃い紫のベタ面で威圧せず、淡い紫面＋明確な「結果不明」ラベルとする。ただし未対応操作として埋もれないよう、カード枠と見出しを purple にする。
- 再印刷の「印字されていない」は通常の主操作、「印字済み」「結果不明」は warning/unknown として承認チェックを要求する。
- バックアップ成果物の「責任者として再生成」は、既存成果物を上書きする操作ではなく新規生成要求なので brand-action。失敗カードからの再生成でも、赤は失敗状態に限定する。

5.11 共通モーダル、エラー、フォーカス

- モーダルの主操作は1つにする。通常の確定は #0b6070、肯定結果は #0f7a52、否定/反転は #9f1239、危険な確定は #b42318。
- 「戻る」「閉じる」は #e7ebef / #27333e。危険操作の隣に置き、誤タップ時に戻れる配置にする。
- エラーは #fef3f2 の面、#b42318 の枠/見出し、本文 #101828。何が失敗したか、会計への影響、次にできることを分ける。
- 結果不明は #f4f3ff / #6941c6。再送ボタンを自動的に肯定色へしない。
- `:focus-visible` は #f59e0b の2px以上の輪郭＋必要に応じて #062f3d の外側輪郭を使う。背景、枠、選択色に埋もれないことを画面ごとに確認する。
- `button:disabled` の透明度だけに依存しない。無効理由を近くに表示し、状態文言も残す。

6. 現行CSSからの置換方針
-------------------------

1. `:root` に上記トークンを追加する。
2. `index.html` の `theme-color` を #062f3d に変更し、ブラウザーのUIでブランド面が読みにくくならないようにする。
3. `styles.css` の `#1d4ed8`、`#166534`、`#b91c1c`、`#9f1239`、`#7c3aed` などを、用途ごとのトークンへ段階的に置換する。
4. 直書き色を単純に全置換しない。同じ緑でも、現金管理入口、成功状態、商品分類が混在しているため、クラス単位で意味を割り当て直す。
5. `.print-status.*`、`.backup-artifact.*`、`.cash-*`、`.return-*`、`.admin-*`、`.customer-*` のように、既存の状態クラスをトークンへ接続する。
6. 部門色・商品タブ色は別の `--pos-color-category-*` 系として扱い、状態色のトークンを流用しない。
7. ロゴ/SVG/manifestの青系固定色が残っていないか確認し、ブランド面 #c0ffee と #062f3d の組合せへ合わせる。ただしアイコン画像は実表示を確認してから更新する。
8. 1回の置換ごとに `pnpm check`、対象UIテスト、`git diff --check` を実行する。

7. 受入確認
-----------

- 起動画面、店員画面、顧客画面、サインオン、業務メニュー、現金管理、運用ダッシュボード、返品、管理画面、再印刷/バックアップのスクリーンショットを取得する。
- 各画面で、主操作、戻る、否定的操作、危険操作、警告、成功、結果不明が同じ意味の色になっていることを確認する。
- 白文字の色付きボタン、淡色面の本文、入力欄の境界、選択行、フォーカスリングをコントラスト計算する。
- 色覚多様性を想定し、色を隠してもラベル・アイコン・線・位置で状態を判別できることを確認する。
- 200%ズーム、横長POS画面、顧客画面、タッチ操作、キーボード操作でフォーカスが見えることを確認する。
- `unknown` を「成功」「失敗」と誤認しないこと、印刷transportの受理と紙面完成を混同しないことを確認する。
- 既存の会計、返品、現金、管理設定、印刷状態の動作契約を変更していないことをテストで確認する。

8. 実装順序の提案
------------------

1. トークン、focus-visible、共通ボタン階層を導入する。
2. 店員画面と顧客画面のブランド・合計・主操作を調整する。
3. 現金管理、返品、運用ダッシュボード、印刷/バックアップの状態色を調整する。
4. 管理画面と起動画面を調整する。
5. スクリーンショットとコントラスト確認を行い、必要な色だけ微調整する。

この順序なら、ブランド色の見た目を先に統一しつつ、会計・現金・返品・印刷の状態意味を失わずに段階導入できる。

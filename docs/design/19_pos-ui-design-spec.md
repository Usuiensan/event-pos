# POS UIデザイン仕様書（参考画像分析版）

## 1. 位置づけ

本書は、提供されたPOS・セルフレジ・現金管理画面の参考画像を、特定製品の画面複製ではなく、`event-pos`で再利用できる業務用UIの設計原則へ抽象化した仕様である。

対象は `apps/register-web` の店員画面、客画面、業務メニュー、現金管理、精算、返品・再印刷・年齢確認などの運用画面とする。既存の会計API・DB・監査・印刷状態の契約を変更する文書ではない。

## 2. 設計原則

1. **業務状態を最優先する。** 商品名や装飾より、現在の取引状態、次に必要な操作、確定可否を優先表示する。
2. **色は意味を固定する。** 部門色や商品ボタンの色は分類用、状態色は操作状態用に分離し、同じ色を複数の意味に使わない。
3. **確定操作には確認と結果を持たせる。** 送信中・結果不明・完了を別状態として表示し、成功を推測しない。
4. **取消は破壊ではなく反転として見せる。** 明細を消さず、取消済みであることと元金額を残す。
5. **店員の判断を客画面へ漏らさない。** 責任者番号、内部エラー、監査理由、在庫・セッション情報は客画面に表示しない。
6. **タッチ、キーボード、マウスを同じ操作モデルにする。** Enter、Escape、Tab順、可視フォーカスを定義する。
7. **状態は文言でも伝える。** 色・音・アニメーションだけに依存しない。

## 3. 画面構成

### 3.1 店員画面（横長）

```text
┌─────────────────────────────────────────────┐
│ セッション／担当者／接続状態／現在の業務       │ ヘッダー
├──────────────────────┬──────────────────────┤
│ 商品登録・部門タブ     │ 登録明細（選択可能）     │
│ 商品ボタン／検索       │ 行番号・商品名・数量…    │
├──────────────────────┴──────────────────────┤
│ 最終登録商品・値引情報・案内帯                  │
├──────────────────────────────┬──────────────┤
│ 取引操作／補助操作              │ 合計・小計     │
└──────────────────────────────┴──────────────┘
```

- 上部は「今どの業務をしているか」を示す。レジ番号、担当者、営業状態、通信状態は小さくても常時確認できる。
- 中央は商品登録と明細を主役にする。明細の縦スクロール位置は保持し、選択行は明確にする。
- 下部は1件のスキャン結果と会計操作を集約する。合計は常に画面右下の固定領域に置く。
- 業務メニュー、数量変更、取消、値引、精算確認などはモーダルで主画面を覆う。背景操作はできない。

### 3.2 客画面（縦長または専用表示）

- 商品名、税込単価、数量、行金額、値引、合計、年齢確認、会計状態だけを表示する。
- 商品登録ボタン、数量変更、取消、支払、責任者情報、内部エラーは表示しない。
- 取引中は明細を読みやすく大きく表示し、合計は画面下部に固定する。
- 会計完了後は、商品・金額・確認結果を消去し、「次のお客様をお待ちしています」等の待機画面へ戻す。
- 商品登録不可時は、操作可能に見える部品を残さず、理由と依頼先を中央に表示する。

### 4.2 色の役割

| 用途 | トークン | 使い方 | 禁止事項 |
| --- | --- | --- | --- |
| 背景 | `canvas` | 画面全体 | 状態を表さない |
| 通常面 | `surface` | 明細、カード、入力欄 | 白文字を置かない |
| 選択中 | `surface-selected` | 選択行、入力対象 | 完了と兼用しない |
| 通常操作 | `action` | 次へ、会計、検索 | 危険操作に使わない |
| 確定・完了 | `confirm` | 確定済み、成功 | 送信中には使わない |
| 警告 | `warning` | 年齢確認、値引、注意 | 単なる選択状態に使わない |
| 危険・取消 | `danger` | 取消、エラー、休止 | 重要文言を色だけで伝えない |
| 合計 | `total` | 合計金額面 | 警告色として再利用しない |
| 部門色 | 個別設定 | 商品分類・タブの識別 | 状態色として解釈させない |

色差だけでなく、ラベル、アイコン、線種、配置の差を併用する。通常文字と背景のコントラストはWCAG AA相当を目標とし、実機輝度・視野角・保護ガラスを含むブラウザー受入で確認する。

## 5. タイポグラフィ、余白、罫線、角丸、影

| 要素 | 仕様 |
| --- | --- |
| 本文 | 16px、行高1.35、濃い無彩色。日本語の商品名は省略せず折返し可 |
| 明細列見出し | 12〜14px、太字、背景色付き。見出しと値を上下で分離 |
| 商品名 | 店員画面20〜28px、客画面22〜30px。長名は2行までを標準 |
| 金額 | 右揃え、桁区切り、単位を必ず付与。合計は36px以上を目安 |
| 案内・補助 | 14px以上。次の操作を動詞で書く |
| 画面余白 | 外周16〜24px、部品間8〜16px、明細行8〜12px |
| タッチ部品 | 高さ44px以上、主要操作は52〜64px。隣接部品間8px以上 |
| 罫線 | 通常1px、区画境界2px。点線は補助境界に限定 |
| 角丸 | 入力・カード6px、主ボタン6〜10px。明細表は過度に丸めない |
| 影 | モーダルのみ強く使用。通常部品は境界線を優先し、押下時は内側影 |

## 6. 共通コンポーネント

### `PosShell`

ヘッダー、業務名、担当者、レジ番号、接続状態、主コンテンツ、下部操作帯を持つ。画面ごとに独自ヘッダーを作らない。

### `StatusBanner`

「商品をスキャンしてください」「指定取消：取消する商品をスキャンしてください」「精算実行中」など、現在の行動を一文で示す。`info`、`warning`、`danger`、`success`、`busy` を持つ。

### `ProductGrid` / `ProductButton`

部門タブと商品ボタンを分離する。部門色は設定データ由来とし、ボタンの状態は別の選択スタイルで示す。空きボタンは押せないグレー面にし、未登録を商品に見せない。

### `DetailTable` / `DetailRow`

商品名、税区分、数量、単価、値引、行金額を列として持つ。選択可能な行はフォーカスリングと背景で示す。客画面では操作列を除外する。

### `SelectedLineSheet`

明細行選択後の操作を「取消」「数量変更」「値引」「閉じる」に限定する。項目の無い空白操作を作らず、現在行の要約を上部に置く。

### `MoneySummary`

合計、点数、お預り、お釣りを右下に固定する。金額の更新時は短いハイライトを許可するが、点滅は使用しない。

### `ActionBar`

通常操作、危険操作、確定操作を左右または色で分離する。主要な確定ボタンは一画面に1つを原則にし、Enterの割当先も同じにする。

### `PosModal`

タイトル、対象、説明・入力、案内、操作ボタン、必要なら番号を持つ。背面は暗幕で操作不能にする。モーダル内の主操作は右下、キャンセルは隣接左側に置く。

### `BlockingProgress`

精算、帳票生成、外部決済記録などで使用する。進捗が取得できない場合は「処理中」とし、完了を推測しない。二重実行を防ぐため、処理中は関連操作を無効にする。

### `DeviceStatus`

プリンター、客画面、ドロアー、サーバーの状態を `ok` / `warning` / `error` / `unknown` で表示する。`unknown` を正常・異常へ読み替えない。

## 7. 商品明細と合計欄

### 店員画面

- 明細は番号付きの行表とし、選択した行を `surface-selected` で強調する。
- 商品登録直後の行は750ms程度の静かなハイライトを許可する。連続スキャンを妨げる大きなアニメーションは不可。
- 値引は「値引前」「値引額」「値引後」を混同させない。自動値引は明細の補助行または値引欄へ表示する。
- 取消済み行は消去せず、商品名・数量・金額に取り消し線を表示し、`取消済み` ラベルを添える。合計と点数からは除外する。
- 指定取消モードは画面下部または明細領域に赤系の案内帯を出し、通常の商品登録状態と区別する。解除方法を常時表示する。

### 客画面

- 行の順序、商品名、数量、単価、金額、値引、合計は店員側の確定済みprojectionから表示する。
- 行をタップしても操作できない。選択色や操作ヒントを表示しない。
- 年齢確認が必要な行は商品名付近に小さな年齢アイコンと「店員確認中」を表示し、身分証情報は表示しない。

## 8. 操作状態

| 状態 | 見た目 | 操作 |
| --- | --- | --- |
| 通常 | 白または淡色面、通常罫線 | 通常操作を許可 |
| 選択中 | 青系背景、2pxフォーカスリング | 対象操作を表示 |
| 処理中 | 案内帯またはモーダル、スピナーは補助 | 二重送信を無効化 |
| 取消済み | 薄い面、赤またはマゼンタの二重線、`取消済み` | 再取消不可 |
| 操作不能 | グレー化、理由ラベル | 無効理由を近接表示 |
| 警告 | 黄／橙の帯、警告アイコン、具体文 | 続行・戻るを明示 |
| エラー | 赤枠または赤帯、原因と復旧方法 | 閉じる／再試行を分離 |
| 完了 | 緑系ラベル、完了文言、次の操作 | 次取引等へ遷移 |
| 結果不明 | 灰色または紫系、`結果不明` | 自動再送せず照会・実物確認 |

取消線は1本の細線だけにせず、行全体に2本の赤系線を使う参考意匠を採用できる。ただし可読性を保つため文字の上端・下端を完全に隠さず、必ずラベルでも意味を補う。

## 9. モーダル構造と操作契約

```text
┌──────────────────────────┐
│ [状態アイコン] タイトル     │  1. 何の確認か
├──────────────────────────┤
│ 対象商品／金額／現在状態     │  2. 何が対象か
│                              │
│ 次に行う操作・注意事項        │  3. 何をすべきか
├──────────────────────────┤
│ 番号・補助情報   戻る  確定   │  4. 結果を確定
└──────────────────────────┘
```

- モーダル幅は横画面の56〜78%、縦画面の92%以内。高さは内容に応じ、画面外へ切れない。
- タイトルは「操作名＋対象」を基本にする。例：「数量変更：玉ねぎ」「精算の確認」。
- 取消・警告は赤い枠だけでなく警告アイコンと文章を併用する。
- 「OK」は確定を意味する文言（「取消する」「精算を実行」）へ置き換える。キャンセルは「戻る」または「やめる」とする。
- 入力モーダルでは現在値、入力対象、単位、入力例、許容範囲を同じ画面に置く。
- 精算は `確認 → 処理中 → 完了／失敗／結果不明` の4段階で、処理中は背景の業務操作へ戻さない。
- エラーは「何が失敗したか」「会計・台帳への影響」「次にできること」を分けて表示する。

## 10. 店員画面と客画面の差分

| 項目 | 店員画面 | 客画面 |
| --- | --- | --- |
| 主目的 | 登録・訂正・会計・運用 | 明細と支払額の透明性 |
| 情報量 | 多い。税区分、操作、印刷状態、担当者等 | 少ない。商品・数量・金額・案内のみ |
| 操作 | 商品登録、行選択、取消、値引、精算 | 原則なし。年齢確認への応答のみ必要なら専用UI |
| 状態 | 業務状態、権限、機器状態を表示 | 登録中、確認中、会計済み、待機のみ |
| 色 | 部門色＋操作状態色 | 背景・合計・警告に限定し、落ち着いた配色 |
| エラー | 原因、復旧、再試行、監査対象 | 「店員をお待ちください」など簡潔な案内 |
| 完了 | 次取引、印刷状態、受付番号 | 完了メッセージ後に待機画面へ |

## 11. 既存プロジェクトへの導入範囲

### 現状確認

- UI実装は `apps/register-web/src/main.tsx` に集約され、店員／客のrole分岐、商品登録、明細選択、支払、取消、値引、年齢確認、業務モーダルが存在する。
- `apps/register-web/src/styles.css` が既存の視覚層であり、今回のトークンはここへ段階的に導入できる。
- `CashOperations`、`OperationsDashboard`、`ReturnOperations`、`HoldOperations`、`AdminSettings` は画面単位のコンポーネントとして分離済みである。
- 既存API・DBは会計確定と印刷job、現金台帳、監査、客画面projectionを分離しているため、UI状態はこれらの結果を表現する層として実装する。

### 推奨する変更単位（未実施）

1. `styles.css` の先頭へ本書のトークンを追加し、既存色を意味別に置換する。
2. `PosShell`、`StatusBanner`、`MoneySummary`、`PosModal`、`DetailTable` を小コンポーネントへ抽出する。
3. `main.tsx` の取消・数量変更・値引・支払・年齢確認・精算表示を共通モーダル契約へそろえる。
4. 店員／客で共有する明細projectionの表示部を分離し、客画面から操作イベントを発生させないことを型・テストで確認する。
5. `ok` / `warning` / `error` / `unknown` と `editing` / `processing` / `completed` / `canceled` を表示モデルとして整理する。
6. 参考画像に近い強い色や取り消し線は、部門設定・状態設定に限定して採用し、製品固有のロゴ・文言・画面配置は採用しない。

### 変更しない範囲

- 商品・取引・現金・返品・監査の正本モデル。
- 会計確定、冪等性、印刷結果不明の扱い。
- プリンターホストやWindows/Linuxの実機対応。
- 客画面へ内部情報を送らないという既存要件。

### 導入時の受入

- iPad横、PC横、縦長の客画面で主要操作が画面内に収まる。
- 取消済み行が読め、合計・点数から除外される。
- 二重tap時に処理中表示となり、結果不明を完了扱いしない。
- 年齢確認、精算、印刷失敗、客画面切断、サーバー切断を色以外の文言でも識別できる。
- 店員画面の内部情報が客画面へ表示されない。
- キーボードのEnter/Escape、タッチ、マウスで同じ業務結果になる。
- 実画面を撮影し、通常・選択・処理中・取消済み・操作不能・警告・完了を確認する。自動テストだけで完了扱いにしない。

## 13. 画像の利用上の注意

- 画像に写る製品名、ロゴ、キャラクター、固有の青いタイトルバー、特定メーカーのボタン配置は再利用しない。
- 画像の色は撮影環境・反射・液晶の経年で変化しているため、色コードの直接採取ではなく、色の役割と階層だけを根拠にする。
- 現金管理や精算の数値・業務文言は参考画像の値を仕様へコピーせず、`event-pos` のAPI・DB状態から表示する。
- 画像中の「OK」「閉じる」等の短いラベルは、そのまま採用せず、業務結果が分かる動詞へ置き換える。
